# Reconcile: research/aidlc-token-review.md vs prd.md + addendum.md

Date: 2026-11-13. Read-only check. Already applied: NFR-10, FR-40, FR-41, FR-42, State HMAC in FR-5. Deliberately not adopted (not listed as gaps): the single-chat, no-subagent model, and the fixed CI retry cap of 3 (addendum §C). Each gap lists the review's words, what the PRD does, where the fix belongs, and severity.

## High

- **§4.4 "Everything else (scope choice, sequencing, checks, gates, commit, push, CI polling, retry cap) is TypeScript" / §2 "the engine owns routing; the model only executes the step it's given"** — FR-5 has `state_get` return "a tool to call", so the cheap Conductor model takes a full turn to call `run_checks`, `test_triage`, `trace_matrix`, `plan_schedule`, `ci_watch` and the Jira and metrics tools. Each turn re-sends the whole chat (review caveat: ~2M input tokens per 40 turns). NFR-1 counts these Stages as "zero model calls", but the Conductor turn is a model call. Nothing requires the server to chain deterministic Stages inside `state_advance`. **Land:** FR-5 and NFR-1. Add "`state_advance` runs every following tool-owned Stage itself and returns only at the next Persona run, Gate or failure". Make SM-3 count Conductor turns spent on deterministic Stages. **Severity: high.**
- **§4.2 "Keep `.github/copilot-instructions.md` under ~150 tokens: name the MCP server and the first call"** — NFR-10 widened the 150-token cap to also cover "the Project Context block loaded every session" (AGENTS.md, FR-37). The review applied the cap to the instructions file only. As written, FR-37's `bmad-project-context` block cannot hold useful repo knowledge. **Land:** NFR-10 and FR-37. Cap only `copilot-instructions.md`, and give Project Context its own budget, delivered per step. **Severity: high.**
- **§3 Review freeze "`pipeline_report(review)` stores the SHA-256 of each reviewed artifact. `pipeline_approve` and `pipeline_commit` recompute the hashes and refuse on mismatch"** — FR-10 freezes only the Spec and the Plan. The code and diff the Reviewers and Synthesizer judged are not hashed. A commit after `validate`, such as a later Goal fix or a hand edit, reaches the `push` Gate with a stale verdict and Walkthrough. **Land:** FR-23 (record the tree hash validated) and FR-26 (the `push` Gate refuses when HEAD or the working tree differs from it, and re-runs validate). **Severity: high.**

## Medium

- **§2 "Results go back as a compact `{pass, findings[]}` (cap the findings)"** — FR-20 caps each failure at 15 lines but sets no limit on how many failures come back. A first lint run on a touched module can return hundreds. **Land:** FR-20 and NFR-1. Add a max finding count per payload from config, plus a "+N more, by file" summary line. **Severity: medium.**
- **§2 Keep (b) item 3 "Rule bundle distilled to ~800 tokens: Testing Posture ..., Construction guardrails (complete files, error handling at boundaries, no secrets, 1 happy + 2 edge-case tests, no `assert True`), Code Style deferral to linter config"** — The PRD sets a 3K budget but never states which rules the implement step carries. The construction guardrails (complete files, boundary error handling, no `assert True`, happy path + 2 edge cases) and the linter-config deferral are lost. SM-C3 ("more tests is not better") may also conflict with "2 edge cases" per file. **Land:** FR-15 (or a new FR "Step rules") plus addendum §F. List the rule set per Persona and reconcile it with SM-C3. **Severity: medium.**
- **§2 "Target: under 3K tokens of framework text per step" vs growing per-step inputs** — FR-36 puts the whole Preferences and Pitfalls docs into every Persona bundle, FR-37 adds the shared knowledge bundle, and FR-22 adds the whole Memlog to every Reviewer bundle. NFR-10 excludes "work content" without saying which side these fall on, so they can grow with no limit and evade the budget. **Land:** NFR-10 (classify them as framework text, or give them their own cap) plus FR-36/FR-22 (filter by Stage or Goal, keep only the last N Memlog entries for the Goal). **Severity: medium.**
- **§2 Keep (b) item 4 "One review prompt (~1K) ... Run it only at the plan gate and optionally at code review"** — The review's one model review is a plan review (adversarial, `READY|NOT-READY`) before the `plan` Gate. The PRD has no plan review. It runs Reviewers only at `validate`, on the code. This may be deliberate, since the human approves the plan, but it isn't recorded as not adopted. **Land:** addendum §C "Not adopted" (one line), or an optional plan-review Stage behind a flag. **Severity: medium.**
- **§2 "Status line, fold-usage, session-cost → `pipeline_status` + token accounting in the server" / §3 Audit "The MCP server logs every tool call it receives"** — The PRD's audit is the Memlog (Stage advances and Gates only). It has no tool-call log and no token accounting, and FR-35 counts "premium requests" the server may not be able to see. Both feed the user's "valuable for future eval". **Land:** FR-35 (estimated tokens per Persona run, from the same bytes/4 estimator NFR-10 already requires) and a new FR or NFR for an append-only tool-call log (JSONL is allowed only if NFR-7 is relaxed; otherwise YAML lines). **Severity: medium.**
- **§3 Continue workflow "the MCP tool returns `next: "call pipeline_ci_status again"`"** — FR-27 says `ci_watch` "polls until a terminal state" with "no model called while waiting". It doesn't say whether that is one long blocking MCP call (timeout risk in Copilot) or repeated Conductor turns (token cost). **Land:** FR-27. Choose one, for example a server-side background watch that sends a notification and is resumed by `start-ticket`, and add it to the OQ list if Copilot tool-call timeouts are unknown. **Severity: medium.**
- **§3 Reviewer scope "Enforcement is soft, because Copilot can't sandbox reads; accept that"** — FR-22 says each bundle "holds" the relevant files. Nothing states that Reviewers can still read beyond the bundle, and per-Stage allowlists (FR-40) are not applied to Reviewers' read tools. A Reviewer that wanders through the repo breaks the context-window sizing the user asked for in Q19. **Land:** FR-40 (Reviewer tool set without workspace read or search tools, bundle inlined) and addendum §C risk line. **Severity: medium.**

## Low

- **§2 Keep (b) items 1, 5, 6 "Loop contract ~300 tokens", "Conductor persona core ~400 tokens", "Question format ~200 tokens"** — The PRD has no content requirements for the Conductor prompt (`start-ticket` SKILL.md plus `conductor.md`). In particular "never edit state", "stop when the directive says stop" and "do not narrate internals" are missing. The general NFR-10 budget applies, but the contract text doesn't. **Land:** FR-5 or addendum §F. **Severity: low.**
- **§2 Port "Conversation-language resolution → a `language` field in the run config"** — Dropped silently. This is a small item for a personal tool, but Spec and Walkthrough language would be left to model guesswork. **Land:** addendum §D `config.yml` key. **Severity: low.**
- **§3 State transition "Put the state file outside the workspace (or keep an HMAC of it in the server)"** — HMAC was adopted, but the key's location is not stated. If the key sits in the workspace, an agent can recompute the HMAC. **Land:** FR-5 consequence (key from an environment variable or a user-profile file outside the workspace). **Severity: low.**
- **§2 Keep (b) item 7 "Personas: only developer + quality, ~200 tokens each"** — The PRD has 9 Personas. They follow user decisions, so this isn't a gap, but no per-Persona prompt cap is stated below the 3K step budget. **Land:** FR-38 (optional per-Persona cap in the generator check). **Severity: low.**
- **§1 caveat "higher after a context compaction, when files are read again" / fixed retry cap not adopted** — The cap was rightly not adopted, but the review's concern was runaway cost. The PRD has no replacement: `same_failure_runs` is counted (FR-7) and only echoed. A rule like "same signature ≥ N → surface to human" would keep "no caps" while stopping silent burn. **Land:** FR-7, tagged `[ASSUMPTION]`, to be confirmed with the user. **Severity: low.** (Raised as medium in the questions file under Q38.)
