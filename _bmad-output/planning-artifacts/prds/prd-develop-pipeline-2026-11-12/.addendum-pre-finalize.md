# Addendum: Agentflow MVP — technical detail for architecture

Companion to `prd.md`. Holds the "how" the PRD deliberately leaves out: tools, files, schemas, build order and design rationale. Carried over from v5 `agentic-workflow-mvp.md`, then updated with the decisions in `.memlog.md`.

## A. Pipeline (updated from v5)

Step numbers match PRD §4.0; this table adds the tool names.

| # | Stage | Owner | Tier | Gate |
|---|---|---|---|---|
| 0 | Bfranchi moves the Ticket to In Execution in Jira (the trigger; no custom label) | Human | none | |
| 1 | Poll (`assignee = currentUser() AND status = "In Execution"`), Intent Record, notify; no Jira transition | Tool | none | |
| 2 | Spec | `intake` | cheap | `spec` |
| 3 | Plan + Waves | `planner` + `plan_schedule` | medium | `plan` |
| 4 | Per Goal: Red → triage → Green → Refactor; commit on status 0 | `implementer`, `refactorer`, `test_triage`, `commit_prepare` | cheap | `escalation` on status 2 |
| 5 | Per-Goal Checks | `run_checks` | none | |
| 6 | Trace Matrix (blocking) | `trace_matrix` | none | |
| 7 | Parallel Reviewers → Synthesizer | `reviewer` ×N, `synthesizer` | cheap, medium | |
| 8 | Walkthrough, push, PR | `committer`, `push_branch` | cheap | `push` |
| 9 | CI watch | `ci_watch`, `ci_failure` | none | |
| 10a | Patch Plan or Correct-Course Proposal → 4…8 | `planner` | medium | `plan` (or `spec`) |
| 10b | In Tests, Jira PR comment, Run Metrics | Tool | none | |

Differences from v5: patch plans are gated; commits are granular and step 8 gates only the push; the trigger is a manual move to In Execution (no label, no intake transition); escalation is human-gated; validation is parallel cheap Reviewers + a medium Synthesizer; checks run per Goal, triggered by status 0.

## C. Hook-free enforcement

Source: `research/aidlc-token-review.md` §3. Two layers: **prevent** where the MCP server owns the action (state, gates, commit, push, CI, Jira) or where the agent lacks the tool; **detect and refuse at the next transition** where it doesn't (file edits with Copilot's own tools).

| Guard (AI-DLC uses a hook) | Agentflow enforcement |
|---|---|
| State transition | `state_advance` refuses non-current Stage or a missing Gate Record; HMAC on `state.yml` detects hand edits (FR-5) |
| Human presence | Gate Records only from `gate_request` elicitation responses; fallback `gate_confirm` tool that Copilot always asks to confirm; no tool takes a decision argument (FR-8, FR-42) |
| Plan approval (no code before approved plan) | **Prevent:** per-Stage tool allowlists, no edit/terminal tools before the `plan` Gate (FR-40). **Detect:** working-tree snapshot at approval, compared at `state_advance(implement)` and `commit_prepare` (FR-41) |
| Review freeze | Artifact SHA-256 stored in the Gate Record; compared before every Stage (FR-10) |
| Sensors on write | Replaced by per-Goal Checks after status 0 and the blocking Trace Matrix |
| Stage-rules delivery | `state_get` returns only the rules that step needs, within the 3K budget (NFR-10) |
| Audit log | `memlog_append` called by `state_advance` and `gate_request`, not by the agent |

Remaining risk: if Copilot doesn't enforce subagent tool allowlists (OQ-8), pre-approval edits are detected at commit, not prevented. Nothing still leaves the machine without the push Gate.

**Token budgets (NFR-10).** AI-DLC measured: ~12K ambient per session, ~51K before stage 1, 15–45K per stage, ~150–250K framework tokens for this pipeline's slice. Agentflow targets: ≤150 ambient, ≤3K framework tokens per step. The generator and `state_get` estimate tokens (bytes/4) and fail when over budget.

**Not adopted from the review:** its single-chat, no-subagent model and its fixed CI retry cap (max 3). Both conflict with recorded decisions (fresh-context subagents; no caps, the human stops the patch loop at the Patch Plan Gate). A CI-verified signed run manifest (approval hashes, check results) is a strong backstop; listed under Future.

## E. Schemas (sketches)

**Plan**

```yaml
goals:
  - id: G1
    acs: [AC-1, AC-2]
    goal: "Orders over $100 get free shipping"
    depends_on: []
    parallel_group: A
    files: [src/shipping/*.ts]
    items:
      - id: G1.I1
        text: "Add free-shipping threshold to pricing rules"
        scenarios:
          - { id: S1.1.1, tag: new, text: "Given a $120 order, When priced, Then shipping is 0" }
          - { id: S1.1.2, tag: existing, text: "Given a $50 order, When priced, Then shipping is unchanged" }
```

**Handoff**

```yaml
handoff:
  id: H-PROJ123-2
  from: { persona: implementer, tier: cheap }
  to:   { agent: escalation, tier: high, role_prompt: prompts/implementer.md }
  reason: stuck | cross_module | spec_conflict | quality_review
  scope:  { goal: G2, items: [G2.I1], scenarios: [S2.1.1], files: [src/a.ts, test/a.test.ts] }
  progress: { iteration: 4, same_failure_runs: 3, status1_retries: 2 }
  attempts: [ { n: 1, approach: "…", result: "…" } ]
  ask: "one sentence"
  constraints: [ "don't change public API" ]
  return: patch_summary | verdict | revised_plan_section
```

**Gate Record**

```yaml
gate: { id: G-3, kind: plan, artifact: plan.md, sha256: "…", decision: approve, elicitation_id: "…", at: 2026-11-12T15:04:00Z, note: "" }
```

**Failure Payload**

```yaml
- { source: test, name: "S1.1.1 free shipping", location: "test/shipping.test.ts:42", message: "expected 0, got 5.99" }
- { source: ci, job: build, step: "npm test", name: "…", location: "…", message: "…" }
```

**Status Code contract (end of every implementer/refactorer run)**

```
AGENTFLOW_STATUS: 0|1|2
AGENTFLOW_SUMMARY: one line
```

```yaml
  reviewer:    { prompt: prompts/reviewer.md,    default: cheap }
  synthesizer: { prompt: prompts/synthesizer.md, default: medium }
  committer:   { prompt: prompts/committer.md,   default: cheap }
  escalation:  { prompt: prompts/escalation.md,  default: high }
tiers: { cheap: <model>, medium: <model>, high: <model> }   # candidates for cheap: Haiku 5.5, luna-6
```

The senior base prompt is a stance, not a Tier: own the outcome, make the smallest correct change, state assumptions, don't gold-plate, and report Status Code 2 with evidence when stuck (same failure after two *different* approaches, cross-module reasoning not loaded, or requirement/test conflict; never on a first failure).

## G. Build order (revised)

1. **Week 1:** layout, `stage-graph.yml`, `state_get`/`state_advance`, `memlog_append`, `gate_request` with elicitation and `gate_confirm` fallback (prove OQ-1 and OQ-8 first), State HMAC, token-budget check in the generator, Jira poller + notification, `start-ticket` skill and Conductor, Persona generator with per-Stage tool allowlists, and Tier config.
2. **Week 2:** Spec and Plan with schema validation, `plan_schedule`, frozen-artifact checks, pre-approval snapshot detection, Preferences/Pitfalls proposals.
3. **Week 3:** sequential TDD loop with Status Codes, `test_triage`, granular commits, per-Goal `run_checks`, `trace_matrix`, `review_bundle`, Reviewers + Synthesizer, Handoff + escalation Gate.
4. **Week 4:** Walkthrough, push + PR, `ci_watch`/`ci_failure`, Patch Plan loop, Correct-Course, In Tests, Run Metrics; then parallel Waves behind the flag.

## H. Design rationale worth keeping

- **Why not wrap the AI-DLC engine directly:** hooks are forbidden on Copilot machines, and the AI-DLC token review measured ~150–250K framework tokens for this pipeline's slice. About 90% is prose explaining the engine contract to the model; a tool interface makes that unnecessary, so the architecture is ported and the text is dropped.
- **Why no review-only agent before Escalation:** each retry already runs in a fresh context, which works as a second opinion; switching between cheap models on retry is a cheap variant.
- **Why no party-mode for spec conflicts:** cost.
- **Why parallel cheap Reviewers:** independent fresh-context opinions catch more than one medium pass, at cheap-Tier cost, provided bundles fit the window. The Synthesizer is the only medium call.
- **Parallel execution tradeoff:** parallel Waves save wall-clock time, not requests; each subagent re-reads its own bundle. Claim-gated launches: each subagent posts its files and intent to the Memlog before acting, and the next one starts only after that, so later agents know where not to act. Claims also let `commit_prepare` refuse edits outside a subagent's own files.

## I. Future (not MVP)

CI-verified signed run manifest (approved hashes, check results, Gate Records) committed with each change; multi-ticket sprint-status board; composer-style ticket triage and right-sized scopes; layered prompt overrides (team and personal); Obsidian vault and RAG/graphRAG retrieval over Memlogs, Pitfalls and code; Jira webhook `TicketSource`; per-Goal git worktrees.
