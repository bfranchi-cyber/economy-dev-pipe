# Reconcile: opportunity-questions.md answers vs prd.md + addendum.md

Date: 2026-11-13. Read-only check. `.memlog.md` used as the decision record (later entries win). Each gap lists the user's own words, what the PRD does, where the fix belongs, and severity. Step numbers in the user's answers use v5 numbering (2 requirements, 3 plan, 4 implement, 5 checks, 6 validator, 7 commit gate, 8 push/CI), which differs from PRD §4.0 numbering.

## High

- **Q1 "Run BMAD skills inside a personalized AI-DLC lifecycle"** — The PRD never runs BMAD skills. It rewrites `bmad-spec`, `bmad-walkthrough` and `bmad-project-context` as its own Personas and prompts (§6 says "from BMAD", FR-11/26/37 say "in the manner of"). That may be the right call for token economy, since the BMAD skill files are large, but it reverses what the user said and has no tag. **Land:** §1 Vision or §6 Method Lineage. Add one explicit statement, either "BMAD skills are distilled into Persona prompts, not invoked" with an `[ASSUMPTION]` tag and the token reason, or name which skills (if any) are invoked as-is. Also mention it in addendum §H. **Severity: high.**
- **Q12 "tests derive from it mechanically" + Q17 trace_matrix** — FR-21 requires a deterministic Scenario → test link, but nothing defines how a test is tied to a Scenario id. The addendum's Failure Payload example `name: "S1.1.1 free shipping"` only hints at it. Without a rule such as "the test name or annotation carries the Scenario id; `trace_matrix` matches on it", the matrix cannot be built without a model. **Land:** new consequence in FR-15 (Red writes one test per Scenario, carrying its id) and FR-21 (match rule, and how an unmatched test is reported). Add a schema line in addendum §E. **Severity: high.**
- **Q42 "sounds great" (bmad-project-context AGENTS.md block) vs NFR-10** — NFR-10 counts "the Project Context block loaded every session" inside a 150-token ambient budget. A `bmad-project-context` block of stable repo knowledge cannot fit in that, so FR-37 is either empty or breaks NFR-10. The user asked for the Project Context; the 150-token cap came from the token review and was meant for `copilot-instructions.md` only. **Land:** NFR-10 and FR-37. Either take Project Context out of the ambient file (deliver it per step inside the 3K or work-content budget) or give it its own stated cap. **Severity: high.**

## Medium

- **Q1 "Uses AI only in MUST use scenario like coding"** — The PRD keeps model calls in places that could be deterministic or templated, and has no rule requiring a reason for each model call. The `committer` Persona (cheap) writes the Walkthrough, though most of it (commit list, files, Trace Matrix rows, "how to test" from Scenarios) can be filled from a template. The Conductor model runs a turn for every deterministic Stage (see the token-review file). **Land:** NFR-1. Add "a Stage gets a model only if it is on an explicit allowlist (spec, plan, implement, refactor, review, synthesize, patch plan, escalation)", and make FR-26's Walkthrough template-first, using a model only for the "what to look at" prose. **Severity: medium.**
- **Q17 "an indicator of re-iterating steps 5 and 6 or not"** — In v5 numbering, steps 5 and 6 are checks and the validator, not implementation. The FR-21 `[ASSUMPTION]` reads it as "back to implementation", and its wording ("steps 5 and 6") now clashes with PRD §4.0, where 5 = Checks and 6 = Trace. The user also called the matrix an *indicator* that decides whether to iterate. The question also placed it at gate 7 (before commit or push). In the PRD it sits before validation and is not re-checked right before the push Gate if validation fixes change things (the loop does re-pass step 6, but the assumption doesn't say so). **Land:** FR-21 assumption text and §11. Restate it using PRD numbers, and confirm that the gap routing is checks → validation re-run vs implementation. **Severity: medium.**
- **Q21 "being two the automatic model escalation" + Q25 "maybe even switching from haiku to luna"** — The PRD hard-codes Escalation as "re-run on the `high` Tier" (Glossary, FR-25, UJ-1). The user described escalation as a model step-up and floated switching between cheap models. FR-9 already shows a "target Tier", which suggests a choice the rest of the PRD doesn't allow. **Land:** Glossary "Escalation", FR-25. Let the Gate choose the target model or Tier (cheap-alt, medium or high), with `high` as the default. **Severity: medium.**
- **Q25 "iterations should be fresh context so naturally a second opinion, maybe even switching from haiku to luna"** — The model rotation idea appears only in addendum §H rationale. FR-16 relaunches a Status `1` retry on the same Tier and model, with no option to rotate. **Land:** FR-16 consequence plus a config key (`retry_model_rotation`), tagged `[ASSUMPTION]` because the user said "maybe". **Severity: medium.**
- **Q21 "a deterministic obligation ... to output 0,1, or 2"** — FR-16 adds "a run without a parseable code is treated as `1`" with no tag. Combined with FR-7 "no caps", a model that keeps forgetting the footer retries forever at full cost. The user asked for the obligation, not for this fallback. **Land:** FR-16. Tag it `[ASSUMPTION]`, and consider "unparseable twice in a row → open the `escalation` Gate" or a human notice. **Severity: medium.**
- **Q21 "per goal, automatically after an implementer agent outputs that it is finished"** — FR-19 triggers Checks on "the Goal's Status Code `0`", but a Goal has two runs (implementer, then refactorer), each with its own code. It is unclear whether Checks run after the implementer's `0`, after the refactorer's, or both. The user tied it to the implementer finishing. **Land:** FR-19 and §4.0 step 4/5. State the trigger point (recommended: after implementer `0` and again after refactorer `0`, since the refactor can break things). **Severity: medium.**
- **Q10 "this should be mapped inside the handoff, the last task of a developer sub-agent should [be] using the commit tool"** — In the user's wording, "handoff" is the subagent's task brief. The PRD narrows "Handoff" to the escalation file only, and FR-17 states the commit rule as a behaviour, not as a required last task in the implementer's input bundle. **Land:** FR-15/FR-17. The input bundle (what `state_get` returns for implement) lists `commit_prepare` as the mandated final task. Note in the Glossary that "Handoff" in the user's sense means task brief, to avoid a clash. **Severity: medium.**
- **Q28 "a doc for user preferences and other for known pitfalls. Valuable." + token economy** — FR-36 includes both docs in *every* Persona bundle and never limits their size, so each ticket makes every later step cost more. The Glossary also says Pitfalls come "from ... failed attempts", but no FR creates Pitfall entries from failed attempts or Escalations. FR-36 only covers Gate edits. **Land:** FR-36. Add a source from Escalation results and Status `2` reasons, filter entries by Persona or Stage, and set a size cap or a dedupe/compaction rule. **Severity: medium.**
- **Q30 "valuable for future eval" + Q31 "reuse part, but personalize"** — FR-35 Run Metrics has no fields needed to evaluate later: concrete model id per run, Persona prompt hash or version, estimated tokens per run, Status Code sequence per Goal, Reviewer vs Synthesizer disagreement. It also doesn't say which AI-DLC `runtime summary` counts are reused (Q31). "Premium requests by Persona" may not be measurable by the MCP server (OQ-2). **Land:** FR-35 fields, and a new OQ on how requests and tokens are counted. **Severity: medium.**
- **Q38 "stop before generating code, wait on user input"** — The user answered this for the CI patch loop. The PRD extends "no caps" (FR-7) to every inner loop (Status `1` retries, Check failures, Trace gaps, validation rounds) on v5 authority. It records no re-confirmation and gives no human stop for those loops. Given the token-economy goal, an inner loop with no stop is the biggest cost risk. **Land:** FR-7. Either confirm with the user, or add a deterministic stall rule (for example "same failure signature N times → open the `escalation` Gate", using counters FR-7 already tracks) and tag it `[ASSUMPTION]`. **Severity: medium.**
