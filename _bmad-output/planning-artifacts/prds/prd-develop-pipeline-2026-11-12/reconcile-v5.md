# Reconcile: v5 decision doc vs PRD + addendum

Source: `agentic-workflow-mvp.md` (v5, 2026-11-11). Compared against `prd.md`, `addendum.md`, `.memlog.md`.
Excluded as deliberate (memlog-backed): patch-plan approval, granular commits / push-only gate, human-approved escalation, parallel Reviewers + Synthesizer, manual In Execution trigger, Claim-gated launches, validator vacuous-test/scope lenses moved to planner (Q18), committer role change.

## High

- **`ask_human` rung and `needs_human` state dropped.** Source: "`ask_human(reason, evidence)` is the next rung. It sets `state: needs_human`, writes a Jira comment, sends a desktop notification ... Typical use: no progress after escalation, ticket ambiguity, or the plan looks wrong." PRD has no `ask_human` tool, no `needs_human` Wait Reason (FR-6 lists only `gate_spec | gate_plan | escalation | push`), and no path for intake/planner/Reviewers to raise ambiguity or for "escalation returned `cannot`" (FR-25 return is defined, its handling is not). Memlog Q21 covers status 2 -> escalation only, not this rung. Land: PRD §4.9 new FR (or FR-25 consequences) + FR-6 Wait Reason + FR-35 metric (`ask_human` calls). Severity: high.
- **Escalation self-evaluation criteria exist only in the addendum.** Source: "call `escalate_model` when the same failure persists after two *different* approaches, when the fix needs cross-module reasoning it hasn't loaded, or when requirement and test conflict. Never on a first failure." PRD FR-16 defines what `2` triggers but never when an agent must/must not report it; the criteria sit only in addendum §F as prompt stance. It is a testable behavioural requirement (and maps to Handoff reasons `stuck | cross_module | spec_conflict`). Land: PRD FR-16 consequences (and FR-38 base-prompt content). Severity: high.
- **No Risks section; accepted risk + passive requests-per-ticket alert silently dropped.** Source: "Accepted risk: a stuck cheap agent may spend several requests before judging itself stuck; a passive alert on requests-per-ticket covers it." and §11 "Cheap-model over-confidence without caps: mitigated by evidence-returning tools, the escalation log, and the passive alert." PRD keeps "no caps" (FR-7) and unbounded status-1 relaunches (FR-16) but has no alert, no threshold, and no risk entry. The no-caps decision depends on this mitigation. Land: PRD new FR under §4.12 (passive alert/notification on requests-per-ticket or `status1_retries`, non-blocking, threshold in config) + a PRD Risks section. Severity: high.
- **Org-policy risk on MCP/skills/subagents dropped.** Source §11: "Org policy may restrict MCP, skills or subagents." Memlog only records the hooks ban. The whole design depends on MCP + skills + subagents; no OQ or risk covers it. Land: PRD §10 Open Questions (prove week 1) or Risks section. Severity: high.

## Medium

- **Test-triage responses lost, and retagging collides with frozen Plan.** Source §5: "`new`/`change` test passed ... The agent retags or strengthens the assertion"; "`existing` test failed: the plan's assumption was wrong"; "Failed for the wrong reason ... fix the test, not the code." PRD FR-18 lists anomalies but not who acts or how. Retagging a Scenario edits `plan.md`, which FR-10 freezes (hash mismatch re-opens the `plan` Gate) - unresolved contradiction; "existing failed" likely needs Correct-Course or a plan Gate. Land: PRD FR-18 consequences (routing per anomaly type; whether retag = plan amendment needing Gate). Severity: medium.
- **Senior-engineer stance content not a requirement.** Source §3: "own the outcome, make the smallest correct change, state assumptions, don't gold-plate, and know when to escalate with evidence ... so every agent behaves like a senior regardless of which model tier." PRD only names "senior-engineer base prompt" (Glossary, FR-38); the content is addendum §F only. Land: PRD FR-38 consequence listing required base-prompt elements (escalation shares the base prompt and runs in the caller's role). Severity: medium.
- **Metrics narrowed vs v5 §10.** Missing from FR-35/§9: gate **reject** rate on Spec/Plan and its purpose ("decides whether to change tiers"); escalations by **persona** (FR-35/SM-5 say by reason only); iterations per Goal **by Tier** and the intent "whether escalating earlier would have been cheaper"; **triage anomaly types**; `ask_human` calls; **ticket-to-PR time** (FR-35 has selection-to-`done`, which includes CI). No memlog decision narrows these (Q30/Q31 only say local + reuse AI-DLC summary). Land: PRD FR-35 fields + SM-4/SM-5. Severity: medium.
- **Reviewer/validator escalation path dropped.** Source §6: validator "may call `escalate_model` for a higher-tier opinion on ambiguous ACs." PRD Status Codes apply only to implementer/refactorer; Reviewers/Synthesizer have no way to escalate or ask, yet Handoff reason `quality_review` remains with no producer. Memlog Q25 drops a review-only agent *before* escalation, not this. Land: PRD FR-22/23 (decide) or mark deliberately dropped and remove `quality_review`. Severity: medium.
- **No notification when a Gate opens.** Source: `ask_human` "sends a desktop notification"; UJ-1 assumes the user is "between meetings". PRD FR-3 notifies only at intake; Gates rely on an elicitation prompt in an open Copilot window. Land: PRD FR-8/FR-9 consequence (desktop notification on every Wait Reason). Severity: medium.
